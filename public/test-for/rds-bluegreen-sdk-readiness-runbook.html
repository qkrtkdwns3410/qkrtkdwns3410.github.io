RDS Blue/Green 문서
01 / SDK READINESS RUNBOOK

SDK로 전환 전 준비 상태를 확인한다

MySQL Single RDS Instance 기준으로 AWS SDK가 Blue/Green deployment, SOURCE/TARGET ARN, switchover status, endpoint, port, DB instance 상태를 수집하는 흐름을 정리한다.

00 목적 01 API 02 SDK 조회 흐름 03 검증 순서 04 IAM
00

목적

이 구현은 JDBC Wrapper 내부 메타데이터 조회 대신 AWS RDS Control Plane API로 Blue/Green 상태를 확인한다.

SDK API 역할배포 존재 여부, role별 ARN, switchover status, endpoint, port, DB instance 상태 확인.
Wrapper 역할runtime JDBC call 보호, connect/execute suspend, reroute, 기존 blue connection 정리.

이 API는 AWS JDBC Wrapper `bg` plugin을 대체하지 않는다. Switchover 전 fleet readiness gate로 사용한다.

01

로컬 API와 Fan-out API

각 EC2 app instance가 제공하는 API

GET  /api/rds-bluegreen/sdk/status
POST /api/rds-bluegreen/sdk/connection-check
POST /api/rds-bluegreen/sdk/operation-probe

주요 query parameter

role=TARGET
deploymentIdentifier=bgd-xxxxxxxx
sourceArn=arn:aws:rds:ap-northeast-2:123456789012:db:source-db
targetArn=arn:aws:rds:ap-northeast-2:123456789012:db:target-db

응답 주요 필드

필드의미
deploymentStatusRDS Blue/Green deployment 전체 상태.
memberStatus선택한 SOURCE/TARGET resource의 switchover 상태.
tasksReadyBlue/Green 준비 task가 모두 완료됐는지 여부.
dbInstanceReady선택한 DB instance가 available 상태인지 여부.
endpointIpsSDK가 선택한 endpoint를 DNS resolve한 IP 목록.
connection.hostIpMatchesExpectedEndpoint설정된 JDBC host DNS가 expected endpoint DNS와 같은 IP를 보는지 여부.
shouldEvictPoolpool refresh 또는 eviction이 필요한지 여부.
shouldBlockWriteswrite를 막아야 하는 상태인지 여부.

Coordinator fan-out API

POST /api/rds-bluegreen/sdk/fanout?region=KR&brand=KIA&role=TARGET&deploymentIdentifier=bgd-xxxxxxxx
POST /api/rds-bluegreen/sdk/fanout/operation-probe?region=KR&brand=KIA&driver=WRAPPER&note=brand-check
02

SDK 조회 흐름

1. DescribeBlueGreenDeployments 호출
2. SOURCE/TARGET ARN 선택
3. SwitchoverDetails에서 member status 확인
4. ARN에서 DB instance identifier 추출
5. DescribeDBInstances 호출
6. endpoint / port / DBInstanceStatus 확인
7. endpoint DNS resolve
8. configured JDBC host DNS와 비교

표준 JDBC API는 이미 만들어진 connection socket의 remote IP를 직접 노출하지 않는다. 따라서 이 구현은 configured JDBC host DNS와 SDK가 선택한 expected endpoint DNS를 비교한다.

`DescribeBlueGreenDeployments.Status`가 `AVAILABLE`이어도 target DB instance가 아직 `modifying`일 수 있다. 그래서 TARGET role의 `DBInstanceStatus=available` 확인이 필요하다.

03

검증 순서

  1. Brand별 여러 EC2 app instance를 실행한다.
  2. 모든 instance가 같은 source RDS MySQL instance를 바라보게 한다.
  3. RDS Blue/Green deployment를 생성한다.
  4. 각 local API를 반복 호출한다.
  5. Coordinator의 global fan-out API를 반복 호출한다.
  6. 모든 target이 `deploymentStatus=AVAILABLE`, `memberStatus=AVAILABLE`, `tasksReady=true`, `dbInstanceReady=true`를 보고할 때까지 기다린다.
  7. Switchover 전 SOURCE / TARGET role을 모두 확인한다.
  8. RDS switchover를 수동 실행한다.
  9. Switchover 중 operation probe를 계속 호출한다.
  10. Plain MySQL JDBC와 AWS JDBC Wrapper `bg` 결과를 비교한다.
curl -X POST "http://{coordinator-private-ip}:8080/api/rds-bluegreen/sdk/fanout?region=KR&brand=KIA&role=TARGET&deploymentIdentifier={bgd-id}"

curl -X POST "http://{ec2-private-ip}:8080/api/rds-bluegreen/sdk/operation-probe?driver=WRAPPER&note=switchover-watch"
