00 / Summary

기본 확인은 권역별 regional fan-out API 호출입니다

핵심은 AWS에서 Blue/Green 배포가 생성되었는지 보는 것이 아니라, 각 권역의 regional fan-out API를 호출해 해당 권역 내부 애플리케이션 인스턴스가 전환 준비 상태인지 확인하는 것입니다. KR, EU, NA, JP, SA가 서로 다른 AWS 리전/내부망이라면 하나의 중앙 API가 모든 권역 인스턴스를 직접 호출하는 구조로 보지 않습니다.

01 / Runtime Proof

방식 1. 인스턴스별 readiness API 확인

무엇을 확인하나

각 애플리케이션 인스턴스가 자기 서버 내부에서 DB 연결 상태와 Blue/Green topology 인지 여부를 확인합니다.

  • 인스턴스별 실제 준비 상태 확인
  • 특정 인스턴스 장애 식별
  • 권역/브랜드 단위 summary 로그 생성

왜 fan-out인가

readiness 상태는 인스턴스별 런타임 상태입니다. 한 서버가 다른 서버의 AWS Wrapper 연결 상태, DB 연결 상태, topology 인지 여부를 직접 알 수 없습니다.

스케줄링 방식은 평상시 로그가 계속 발생하고, 전환 시점의 최신 상태 판단이 어렵습니다. 필요한 시점에만 확인하려면 각 권역의 regional API가 같은 권역 내부 인스턴스로 fan-out 호출하는 구조가 맞습니다.

API 호출 기준

EventBridge가 되면 자동 트리거로 연결하고, 어렵다면 운영자 또는 배포 파이프라인이 아래 API를 직접 호출합니다. 권역은 서로 다른 AWS 리전/내부망이므로 하나의 중앙 API가 전체 권역으로 fan-out하지 않습니다.

예: KR endpoint는 KR 내부 인스턴스만, EU endpoint는 EU 내부 인스턴스만 fan-out합니다. 운영 절차는 필요한 권역 endpoint를 각각 호출하고 결과를 Hubble/OpenSearch에서 확인합니다.

장점

  • 실제 애플리케이션 서버 기준으로 준비 상태를 확인할 수 있습니다.
  • 특정 서버만 준비되지 않은 경우 바로 식별할 수 있습니다.
  • 권역/브랜드별 전체 준비 여부를 분리해서 볼 수 있습니다.

고려사항

  • 호출 대상 인스턴스 목록을 관리해야 합니다.
  • 권역별 regional endpoint 목록을 운영 절차나 배포 파이프라인이 알고 있어야 합니다.
  • fan-out 호출 timeout과 일부 실패 처리가 필요합니다.
  • 스위치오버 직전에 실행하는 운영 절차가 필요합니다.

권장 순서

  1. ALB Target Group, Cloud Map, ECS/Kubernetes service discovery에서 현재 대상 조회
  2. SSM Parameter Store 또는 AppConfig에 권역 내부 브랜드별 discovery source 저장
  3. 초기 단계에서만 정적 설정 사용

Security Group 기준

KR 내부에서 Kia, Hyundai, Genesis가 같은 SG 또는 호출 가능한 SG 묶음에 있으면 하나의 KR regional API가 세 브랜드를 모두 확인할 수 있습니다.

브랜드별 SG가 분리되어 호출이 막혀 있다면 브랜드/SG 단위로 fan-out을 나누거나 regional API SG에서 각 브랜드 SG로 ingress를 허용해야 합니다.

Secrets Manager는 왜 아닌가

인스턴스 IP나 내부 URL은 비밀번호나 API key가 아닙니다. 따라서 secret 저장소가 아니라 서비스 위치 정보 또는 운영 설정으로 관리하는 편이 자연스럽습니다.

SG는 대상 목록 저장소가 아니라 호출 가능한 네트워크 경계로 보고, 대상 목록은 discovery/config에서 관리하는 편이 맞습니다.

03 / AWS Event Signal

방식 2. AWS EventBridge 기반 확인

동작 방식

  1. RDS Blue/Green 배포 상태 변경 이벤트가 발생합니다.
  2. EventBridge rule이 해당 이벤트를 감지합니다.
  3. Lambda, SNS, 배포 파이프라인 등으로 이벤트를 전달합니다.
  4. 필요 시 readiness fan-out을 실행합니다.

좋은 점

  • AWS 리소스 상태 변화를 자동으로 감지할 수 있습니다.
  • Blue/Green 배포 완료, 실패, 스위치오버 이벤트를 알림으로 연결하기 쉽습니다.
  • Lambda, SNS, SQS 등 AWS 서비스와 연동이 쉽습니다.

알림 또는 readiness 확인

EventBridge는 AWS 리소스 이벤트를 알려주는 장치입니다. 각 애플리케이션 서버가 실제로 Green DB를 인지했는지는 알 수 없으므로, EventBridge만으로 전체 서버 전환 준비 완료를 판단하면 안 됩니다.

04 / Recommendation

권장안. 권역별 regional fan-out을 기본 절차로 둡니다

최종 판단 기준

switchover 전 최종 판단은 각 권역의 regional fan-out 결과가 브랜드별로 allReady=true인지 확인하는 것입니다. EventBridge는 가능할 경우 권역별 fan-out 호출을 자동화하는 보조 수단으로 둡니다.
