수집 API 완료 판정 후 switchover는 성공했다

Single RDS MySQL Blue/Green switchover에서 직접 만든 SDK 수집 API가 완료 상태를 보고한 뒤 switchover를 실행했고, 실제 전환과 JDBC 동작이 어떻게 나왔는지 정리한 결과 문서다. 실제 리소스 식별자는 공개 페이지 기준으로 샘플값으로 마스킹했다.

01

Deployment AVAILABLE만으로는 부족했다

첫 번째 switchover 시도는 `DescribeBlueGreenDeployments` 기준 deployment 상태가 `AVAILABLE`이었지만 실패했다.

InvalidBlueGreenDeploymentStateFault:
DB instance rds-bg-wrapper-lab-blue-green-xxxxxx is not in available state

당시 target DB instance 상태는 다음과 같았다.

DBInstanceStatus=modifying

Readiness gate는 deployment 상태와 target DB instance 상태를 함께 확인해야 한다.

DescribeBlueGreenDeployments.Status == AVAILABLE
selected target DescribeDBInstances.DBInstanceStatus == available
02

수집 API가 완료라고 판단한 뒤 switchover했다

두 번째 검증에서는 직접 만든 SDK 수집 API가 SOURCE/TARGET 상태를 다시 수집했고, switchover 전 target 기준 준비 조건이 모두 충족된 것을 확인했다. 

deploymentStatus=AVAILABLE
memberStatus=AVAILABLE
tasksReady=true
dbInstanceReady=true
ready=true
fanoutSucceeded=3
fanoutFailed=0

이 완료 판정을 기준으로 RDS Blue/Green switchover를 실행했다. Switchover 이후 AWS 최종 상태는 다음과 같이 완료로 확인됐다. 

Final AWS state=SWITCHOVER_COMPLETED
OK수집 API가 target DB instance까지 available 상태로 확인했다.
OK그 완료 판정 이후 switchover를 실행했다.
OKSwitchover 결과는 SWITCHOVER_COMPLETED로 끝났다.

결론적으로 “수집 API가 완료라고 말했을 때 switchover를 진행해도 되는가”에 대해서는 이번 Single RDS MySQL 검증에서는 정상 동작으로 확인했다. 단, runtime 중 발생하는 JDBC 오류 흡수는 SDK 수집 API가 아니라 AWS JDBC Wrapper `bg` plugin의 역할이다.

03

Probe 방식

각 EC2 instance는 같은 local API로 Plain MySQL JDBC와 AWS JDBC Wrapper 경로를 모두 실행했다.

POST /api/rds-bluegreen/sdk/operation-probe?driver=MYSQL
POST /api/rds-bluegreen/sdk/operation-probe?driver=WRAPPER

각 probe는 switchover window 동안 180회 write를 시도했다.

180driver별 write 시도 횟수
3검증 대상 app instance
2Plain MySQL JDBC / Wrapper 경로

05

해석

Plain MySQL JDBC

Switchover 중 read-only error와 timeout이 operation API까지 노출됐다.

AWS JDBC Wrapper bg

같은 switchover window에서 SQL-level write failure를 회피했다.

따라서 SDK readiness API와 AWS JDBC Wrapper의 역할은 분리해서 봐야 한다.

구분역할
SDK readiness APISwitchover 전 deployment/resource 상태 확인, target DB instance `available` 확인, region/brand/fleet 단위 readiness 확인. 이번 검증에서는 이 API가 완료로 판단한 뒤 switchover를 실행했고 최종 상태가 `SWITCHOVER_COMPLETED`가 됐다.
AWS JDBC Wrapper `bg` pluginRuntime JDBC call 보호, switchover 중 connect/execute suspend, blue/green reroute, 기존 blue connection 정리.
